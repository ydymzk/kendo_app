## 1. サービス概要

サービス名：KENDO守破離

「勘」や「記憶」に頼りがちな剣道の稽古を、思考と試行錯誤のプロセスへ変える稽古ログサービスです。
相手の特徴や技を出す「機会」、YouTubeなどで学んだ新しい技の感覚を言語化して蓄積できます。
技の習熟度を可視化し、レパートリーを確実に増やす「修練の稽古」を実現します。

誰の：
得意技の精度を上げたい、新しい技を身につけたいと願うすべての剣道家。

どんな課題：
自分の得意技を「どんな相手に・どんな機会（タイミング）で出しているか」が感覚的で可視化できていない。
YouTubeなどで学んだ新しい技を真似して練習しても、稽古後の感覚や気づきを記録しないため、
次の稽古に活かされず忘れてしまう。

どう解決するか：
「守」「破」「離」の習得段階に分けて、技を出す条件（相手の体格・クセ・タイミング）を記録・言語化する。
見取り稽古や日々の稽古で得た感覚・改善点を蓄積し、次の稽古へ向けた具体的な課題設定を可能にする。
・守：見取り稽古やYouTubeを見て他人が出していた技、真似したい技を見つけた段階
・破：稽古で真似をして得た感覚や改善点に基づき試行錯誤している段階
・離：自分の想定していた技を出す条件や感覚が当てはまり、試合で一本取れるようになった段階

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

剣道の理念は「剣の理法の修練による人間形成の道」です。
年齢に関わらず生涯を通じて続けられる競技であり、年齢や段位、体格に関わらず稽古や試合をする場面が多い。
専ら試合に関しては、構えた状態から相手に技が届くまで約0.2秒という一瞬の速さで勝敗が決まってしまう。

そのため経験に基づき瞬間的に次の行動を判断する、技を出す際も相手の次の行動を予測する必要がある。
どんなに早い技が出せても、何の技を出すかわかっていれば確実に防がれてしまう。

試合や試合稽古の中で相手の特徴（体格やクセ）を把握し、相手の次の行動を予測した上で、
適切な機会（タイミング）で適切な技を出すことが重要である。

私自身、剣道を始めて約30年が経ち、昨年には6段に昇段したが、自分の得意技に関してもどんな相手に
どんな機会で技を出すのか感覚的にあるだけで見えるようになっていない。

また新たな技を習得するためにYouTubeで強い選手の技を見て普段の稽古でその技を真似て練習するが、
練習の中で学んだことや感覚を記録することもなく、次の稽古では覚えていないことが多い。
強い選手ほど、どんな相手と対戦しても対応できるように技のレパートリーが豊富。

稽古を単に体を動かす時間とせず、技の修練ができるように変えていきたい。

### 2-2. なぜそれが「気になった」のか

社会人になってからも日々稽古を続け、実業団の大会でもそれなりの成績を収めてきた。
但し、結婚し子供が生まれてからこの数年間は稽古をする頻度が格段に減り、大会の成績も良くない。
隙間時間で剣道関連のYouTubeを見ることは出来ているが、実際の稽古量を増やすことは出来ないので、
限られた稽古時間の中でいかに「質の高い稽古」ができるか、効率や再現性を追求する必要性を感じた。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

・稽古量が減り、YouTubeなどで見つけた新しい技や稽古での気づき・感覚を試行錯誤しても、
　記録に残さないため次の稽古までに忘れてしまい、技が身につかない。

・自分の得意技について、「どんな相手に・どんなタイミングで出せているか」が感覚的にしか
　把握できておらず、実戦で狙って再現できない場合もある。

### 3-2. 本当に解決したい課題は何か

1回目の「なぜ？」：なぜ、新しい技や感覚を忘れてしまうと困るのか？
→ 限られた稽古時間の中で試行錯誤した時間や、YouTubeで研究した知識が無駄になり、
　稽古の質が上がらず「ただ体を動かしただけ」で終わってしまうから。

2回目の「なぜ？」：なぜ、稽古の質が上がらないと困るのか？
→ 家族に協力してもらって稽古や試合に参加させていただいているにも関わらず、
　自分の成長を実感できず大会の成績も落ちているため。

3回目の「なぜ？」：なぜ、自分の成長を実感できず大会の成績が落ちると困るのか？
→ 一緒に試合に出場している若手部員の剣道に対するモチベーションを下げてしまい、
　剣道部、延いては会社に対する帰属意識が失われてしまうため。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

30代後半〜40代前半・既婚（幼い子あり）・実業団剣道部に所属する社会人剣士

年齢設定：
30代後半〜40代前半
→ 20代の頃のように「週に何度も稽古に打ち込む体力・時間的自由」がなくなり、
　一方で40代後半以降のように「子供が独立して自分の時間が再び増える」状態でもない、
　人生で最も時間の制約が厳しい年代だからです。

生活・状況設定：
仕事ではチームリーダーや管理職として責任が増し、家庭では育児や家事に奔走している。
稽古参加は家族の理解と協力があってこそ成り立っており、「せっかく作ってもらった
時間だから無駄にしたくない」という状況。
→ 稽古回数を増やせない状況だからこそ、1回の稽古の前後で「YouTube等での事前研究（守）」
　「稽古での試行錯誤（破）」「言語化と定着（離）」をアプリ上で短時間かつ効率的に回すことで、
　短時間で「質の高い稽古」を実現できます。

環境設定：
会社の剣道部に所属し、実業団大会に出場している。若手部員を引っ張る立場・手本となるべき存在であり、
隙間時間（通勤中や就寝前）にスマートフォンを日常的に活用している環境。
→ 稽古場でノートを開いてメモを取る時間はなく、記憶が薄れるのも早いため、移動中や隙間時間で手軽に
　「技の条件」や「感覚」を入力・言語化できる仕組みが必要です。

### 4-2. 自分とユーザーの距離

自分自身
→ 私自身がまさに「30代後半・子育て中・実業団剣道部所属」であり、限られた時間の中でいかに
　稽古の質を上げ、自分の技（得意技や新しい技）を「守・破・離」のプロセスで言語化・定着させるかという
　課題に今まさに直面しているからです。

### 4-3. 実際に使われる可能性について(需要・存在確認)

□まず最初に使ってくれそうな人は誰か？：
自分自身及び会社の剣道部の同僚・後進、稽古仲間の社会人剣士
（特に自分と同様に、子育てや仕事で稽古時間が限られている30代後半〜40代前半の剣士）

□その人は、どんな場面でこのアプリを思い出すか？：
・通勤中や就寝前（隙間時間）
→ YouTubeで強い選手の技動画を見たり、次回の稽古で試したい技を思いついた瞬間（「守」の段階）。

・稽古直後・帰りの移動中
→ 稽古が終わり、「今日のあの技を出すタイミング（機会）は良かった」「真似してみたけれどここが
　上手くいかなかった」という感覚が頭に残っている瞬間（「破」の段階）。

・試合・審査後の振り返り
→ 「自分がどんな相手に一本を取れるパターンを持っているか」を整理・確認したい瞬間（「離」の段階）。

□今の生活の中で、代わりに使っているものは何か？：
頭の中の記憶のみ（何も記録せず、稽古の数をこなすだけ）

□置き換えてまで使う理由はあるか？：
・「記憶だけに頼る稽古」からの脱却と再現性の獲得
→ 「頭の中の記憶だけでは、数日経つと稽古での感覚や気づきが薄れ、毎回「ゼロからの試行錯誤」に
　戻ってしまいます。スマホで短時間で言語化・視覚化しておくことで、限られた稽古時間でも前回の続きから
　質の高い稽古を再開できます。

・「守・破・離」の成長実感によるモチベーション向上
→ ただ漠然と稽古を重ねるのではなく、YouTubeで見つけた技（守）が、試行錯誤（破）を経て、
　試合で一本が取れる自分の武器（離）へと育っていくプロセスが数値・データとして可視化されるため、
　稽古回数が少なくても確実な成長実感を得ることができます。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

□どんな場面・困りごとがきっかけで、このサービスを知る・思い出すか：
稽古後に「今日のあの技、良い感覚だったのに次の稽古では絶対に忘れているな…」と焦りを感じた帰り道や、
通勤中にYouTubeで強い選手の技を見て「次の稽古で試したいが、また流れてしまいそう」と
もったいなく感じた瞬間。同じ悩みを持つ会社の剣道部の同僚・後進からの紹介される。

□最初の一歩（登録・導入）で、ユーザーは何をする必要があるか：
アカウントを作成し、「真似したい技」あるいは「自分の得意技」を1つ登録する。
最初から完璧にノートを作らせるのではなく、「技を1つ登録するだけ」でスタートできる手軽さを重視。

□利用を続ける理由は何か？（習慣・必要性・価値）
・習慣：
稽古前にその日試す「守・破」の技を確認してテーマを持って稽古に臨む。
稽古後に「機会（タイミング）」や「感触」等をメモする（数分で完了）。

・価値：
見よう見まねだった技（守）が、試行錯誤（破）を経て、実戦で一本取れる技（離）へステータス移行していく。
稽古量が少なくても「着実に自分の技のレパートリーが増えている」という実感が得られるため、
自発的に記録を続けたくなる。

・必要性：
記録が溜まるほど「自分がどんな相手・どんな機会で一本を取れるか」のパーソナルデータが完成するため、
試合や審査の前には欠かせない「自分だけの秘伝の書」として手放せない存在になる。

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

□サービス名：剣道ノート

□URL：https://play.google.com/store/apps/details?id=jp.creativemap.kendo_note&hl=ja&pli=1

□どんなことができるか：
・大会管理機能
→ 公式大会、練習試合、昇段審査など、あらゆる種類の大会を一元管理。大会ごとに試合記録を整理し、
　過去の戦績を簡単に振り返ることができます。

・試合記録機能
→ 公技の種類（面・小手・胴・突き）や反則をタップするだけで簡単に記録できます。

・分析機能
→ 記録した試合データから、詳細な分析レポートを自動生成。自分の強みや改善点を数値で把握できます。

・稽古メモ機能
→ 日々の稽古内容を記録し、目標設定と進捗管理を行えます。過去のメモを振り返ることで、
　継続的な上達をサポートします。

### 5-2. それでも自分が作りたい理由

□既存サービスに感じた違和感・不満：
・「結果（勝敗・スコア）」は残せても、「そこに至る試行錯誤の過程」が残せない
→ 既存のアプリは「どの大会で、どんな技で勝った/負けた」という結果の記録が中心でした。
　しかし、私が本当に記録したいのは「一本取れた理由」であり、「動画を見て真似してみた技が、
　稽古でどういう感覚だったか」「どんな相手の、どの機会（タイミング）なら技が出せるのか」という
　泥臭い試行錯誤のプロセスです。
　数字や勝敗の管理だけでは、稽古の質を上げるためのヒントにはなりませんでした。

・「技を育てる楽しみ」を感じられない
→ 試合データの集計や分析グラフを見ても、稽古回数が減っている自分にとっては「稽古量が足りない」
　「最近試合に出ていない」という事実を突きつけられるだけで、モチベーションが上がりにくい構造でした。
　そうではなく、YouTubeで見つけた技（守）を稽古で試し（破）、実戦で使える技（離）へと
　「自分の技のレパートリーを育てていく感覚」が得られる場所が欲しかったのです。

### 5-3. 差別化を「体験価値」で表現する

□私のアプリの差別化ポイント：
「限られた稽古量しか取れない社会人剣士が、稽古前後のわずか3分で『自分の技が育っている』という
確実な成長実感を得られる体験」

□具体的な体験価値：
・【稽古直後】結果に落ち込まず、試行錯誤のプロセスを楽しめる体験
→ 単に試合の勝敗や本数（数字）を記録して一喜一憂するのではなく、YouTubeで見つけた技が
　「稽古でどう手応えがあったか」を言語化することで、稽古量が少なくても
　「着実に技の引き出しが増えている」という前向きな手応えを得られます。

・【稽古直前】迷いなく「明確なテーマ」を持って稽古に臨める体験
→ 道場に向かう途中でサッとアプリを開くだけで、今日試すべき「守・破」の技と着眼点がクリアになり、
　1回1回の稽古の質を劇的に高められます。

・【試合・審査前】自分だけの『秘伝の書』を手に、自信を持って試合や審査に臨める体験
→ これまで勘に頼っていた「自分がどんな相手に・どの機会（タイミング）で一本を取れるか」が
　文書として可視化されているため、大切な試合や昇段審査の前に「自分にはこの勝ちパターンがある」
　という確固たる根拠を持った自信を手に入れられます。

## 7. このアプリで実現すること

□ユーザー管理機能：
新規会員登録、ログイン・ログアウト（メール・パスワード認証）

□「守・破・離」技管理機能（コア機能）

　技名（例: 引き面）、技を出す条件（相手の体格・クセ・タイミング）、ポイントメモ（手応え・感覚）、
　参考動画URL（YouTube等）

・ステータス管理: 
　ワンタップで「守（見取り）」「破（試行錯誤）」「離（実戦定着）」の段階を変更

・技一覧表示（ダッシュボード）: 
　「守」「破」「離」ごとに分類された技カードの一覧表示

### 本リリースで作る機能

□稽古ログ記録機能
・テーマ選択：
　稽古前にその日試す技（「守・破」に該当するもの）を1つ以上選択

・振り返り入力：
　稽古後に「試せた/試せなかった」の判定、技を出す条件（相手の体格・クセ・タイミング）の修正、
　ポイントメモ（手応え・感覚）の修正

□技ごとの振り返り履歴表示：
　1つの技の詳細画面で、その技に関連する過去の記載内容とステータスの変化を時系列で閲覧できる機能

□成長チャート：
　登録した技が「守」から「破」へ、「破」から「離」へ移行した数の推移グラフ化

## 8. このアプリの懸念点とその対策

### 懸念点①

□何が問題になりそうか：
「稽古後の入力自体が面倒になり、アプリの利用が習慣化せずに途絶えてしまうこと」

□なぜそう思うか：
稽古後は肉体的に酷使されており、仕事・家事・育児で慌ただしい時間が続きます。
どれだけ「守・破・離」のコンセプトが素晴らしくても、1回の入力に時間が掛かる手間や
思考コストが掛かると、仕事や家庭で忙しいターゲット層は数回で開かなくなってしまう懸念がある。

□そのために考えている対策：
・「数分で完結する」超軽量な入力設計（MVP段階からの徹底）：
　技を出す条件、ポイントメモ、参考動画URLは任意の記入項目とし、技名だけを必須とする。

・「稽古前」を起点にした習慣化設計：
　稽古前に「今日のテーマを1つ見るだけ」という低負荷なアクションを習慣化のフックにします。

## 9. 今後の展開・発展の方向性

### 観点

□ユーザーはなぜ使い続ける？：
　単なる勝敗や数字の記録ではなく、「見よう見まねの技（守）」が「実戦で使える自分の武器（離）」へ
　育っていく成長プロセスそのものが可視化されて面白いから。
　また、稽古直前に見るだけでテーマが明確になるため、「使うと稽古の質が上がる」という実用性を感じるから。

□続けることで何が変わる？：
　ただ数をこなすだけの稽古から脱却し、「課題意識を持って稽古に臨み、短時間で成果を出す思考サイクル」が
　自然と身につきます。
　また、稽古量が少ない時期でも「着実に技の引き出しが増えている」という自信が積み重なります。

□データが溜まると何ができる？：
　「自分がどんな体格・クセの相手に、どの機会（タイミング）で一本を取りやすいか」という独自の勝ちパターンや
　得意な状況が自動整理されます。これにより、「自分だけの秘伝の書」として確認できるようになります。

□他の人と関わる余地はある？：
　過度なSNS的コミュニケーションではなく、「他の剣士がどんなYouTube動画や指導の言葉を『守』として
　登録しているか」という着眼点（ナレッジ）の匿名共有をする。他の剣士の試行錯誤を「見取り稽古」として
　参考にできるゆるい繋がりを生み出す。

### 今考えている発展案

□機能追加の方向性：
・パーソナルデータの自動可視化（勝ちパターンの抽出）
　記録が溜まることで、「自分はどのような体格・クセの相手に、どの機会（タイミング）で
　一本を取りやすいか」が自動で傾向分析され、試合や昇段審査前の「自分専用の戦略シート」として
　閲覧可能になる。

□UI・体験の改善：
・稽古直前のワンタップ通知
　現在「守・破」に設定している「今日のテーマ技」を通知し、アプリを開く手間を省いて
　稽古に集中できるようにする。

□機能以外の工夫：
・「守（見取り）」のオープン共有ライブラリ
　「他の剣士がどんなYouTube動画や指導の言葉を『守』として登録しているか」の知見（着眼点）のみを
　匿名で参照・ブックマークできるナレッジ共有機能。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

□フレームワーク：Ruby on Rails
□DB：MySQL
□デプロイ先：Render、Docker
□使用予定ライブラリ：devise、Tailwind CSS

### 10-2. 技術選定の比較検討

□フレームワーク
| 候補 | 採用/不採用 | 理由 |
| Ruby on Rails | 採用 | 開発速度が非常に高く、情報量が豊富でエラー解決がしやすい |
| Laravel (PHP) | 不採用 | 学んだカリキュラムの軸がRuby/Rails中心であるため |
| Node.js (Express) | 不採用 | 認証やDB接続などの初期構築・ディレクトリ構成の設計コストが高いため |

□今回チャレンジしたい点：
これまでカリキュラムで学んだことを応用して、一からアプリを作成する。

□不安な点：
仕事・育児・家事・稽古の合間での開発となるため、MVPの機能を欲張らずにシンプルに保ち切れるか。

### 10-3.キャッチアップ不足の懸念

キャッチアップ不足の段階では以下の懸念点があります。
1. **完成までのハードルが高い**
使用する言語やフレームワークが異なるため、キャッチアップにかかる時間は個人差があるものの、
一定の時間を要することが予想されます。

2. **Issueの見積もりが難しい**
「どこまで理解していて、何が分からないのか」「調査にかかる時間」などが不明瞭な場合、
開発期間内に完了することが難しくなってしまいます。

MVP段階：使い慣れた技術で最速リリースを目指す
→ 最初からReact等で構築するのではなく、学習コストを抑えられるRuby on Rails を採用します。

本リリース以降：段階的な検証とReact化の検討
→ アプリ全体のMVP（または本リリース）が完成し、Railsでの基礎開発・運用に余裕ができたタイミングで
　Reactのキャッチアップを開始します。
